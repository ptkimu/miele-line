# ミエーレ LINE配信システム — フェーズ1

ビューティサロン ミエーレ の LINE公式アカウント連携。
Cloudflare Workers + D1 で動きます。

**このフェーズでは通数を1通も消費しません。** 送信に使うのは応答メッセージ（Reply API）だけで、
LINEの通数カウント対象外です。ライトプランの 5,000通/月 は手つかずのまま残ります。

## できること

| 機能 | 内容 | 通数 |
|---|---|---|
| 友だち追加の記録 | `follow` を受けて D1 に登録。表示名も取得 | 0通 |
| ブロックの記録 | `unfollow` を受けて status を blocked に | 0通 |
| キーワード応答 | 予約・営業時間・アクセス・メニューなどに自動返信 | 0通 |
| 来店の記録 | スタッフ用ページから、次回予約の有無つきで記録 | 0通 |
| 未対応質問の可視化 | 自動応答できなかった質問を集計 | 0通 |

自動応答できない質問には **あえて返信しません**。「わかりません」と返すより、
スタッフがLINEチャットで答えたほうが良いためです。LINEチャットの送受信も通数は無料です。

## セットアップ

### 0. Node.js をインストールする

このPCには Node.js が入っていません。先に <https://nodejs.org/> から LTS 版を入れてください。
インストール後、新しいターミナルで確認します。

```bash
node -v
npm -v
```

### 1. 依存をインストールして Cloudflare にログイン

```bash
cd C:/Users/ptkim/miele-line
npm install
npx wrangler login
```

### 2. D1 データベースを作る

```bash
npm run db:create
```

出力される `database_id` を `wrangler.toml` の `PASTE_DATABASE_ID_HERE` に貼り替えます。
続けてテーブルを作ります。

```bash
npm run db:init
```

### 3. LINE の認証情報を登録する

[LINE Developers コンソール](https://developers.line.biz/console/) で対象チャネルを開き、
**Messaging API 設定** から次の2つを取得します。

- チャネルシークレット
- チャネルアクセストークン（長期）

```bash
npx wrangler secret put CHANNEL_SECRET
npx wrangler secret put CHANNEL_ACCESS_TOKEN
npx wrangler secret put ADMIN_USER      # スタッフ用ページのユーザー名
npx wrangler secret put ADMIN_PASS      # スタッフ用ページのパスワード（英数字で）
```

### 4. 店舗情報を埋める

`src/salon.js` の `★ TODO` を実際の値に置き換えます。

```js
hours:   '10:00〜20:00（最終受付 19:00）',
closed:  '毎週火曜日',
tel:     '0280-00-0000',
parking: '店舗裏に3台分ございます',
```

**null のままの項目は、その話題の自動応答が無効になります。**
間違った営業時間を自動で答えてしまうより、スタッフに回したほうが安全なためです。

### 5. デプロイする

```bash
npm run deploy
```

`https://miele-line.＜サブドメイン＞.workers.dev` が発行されます。

### 6. Webhook を設定する

LINE Developers コンソールの **Messaging API 設定** で、

- Webhook URL … `https://miele-line.＜サブドメイン＞.workers.dev/line/webhook`
- Webhookの利用 … オン
- 応答メッセージ … **オフ**（このシステムが返すため）
- あいさつメッセージ … **オン**（管理画面で文面を編集。通数は無料）

「検証」ボタンで成功すれば接続完了です。

## 使い方

### スタッフ用ページ

```
https://miele-line.＜サブドメイン＞.workers.dev/admin
```

会計のあと、来店されたお客様を名前で検索してボタンを押します。

- **来店・予約あり** … その場で次回予約が取れた方
- **来店・未予約** … 取れなかった方

フェーズ3のリマインドは **未予約の方だけ** に届きます。予約済みの方に
「そろそろですね」と送らないための区別です。

前回来店から11日以上たった未予約の方は、一覧で赤いタグが付きます。
2〜3週サイクルの手前で気づけるようにしています。

### 自動応答できていない質問を見る

```
/admin/questions
```

よく聞かれるのに答えられていない質問が並びます。
`src/replies.js` の `RULES` に追加すれば、次から自動で答えられます。

コマンドラインからも確認できます。

```bash
npm run db:unmatched
npm run db:friends
```

### ログを見る

```bash
npm run tail
```

## 設計上の判断

**署名検証を必ず通す** — `X-Line-Signature` をチャネルシークレットでHMAC-SHA256検証します。
一致しないリクエストは401で弾きます。検証は `JSON.parse` する前の生ボディに対して行う必要があります。

**Webhookには即座に200を返す** — 応答が遅いとLINEがイベントを再送します。
`ctx.waitUntil` でレスポンス後に処理を続けます。

**同じイベントを二度処理しない** — 再送に備えて `processed_events` に `webhookEventId` を
記録し、既にあれば何もしません。

**来店記録はスタッフ用ページで行う** — LINEのWebhookに届くのはお客様から届いたメッセージだけで、
スタッフが管理画面から送った返信はイベントとして飛んできません。
そのため「スタッフがトークに `#来店` と打つ」方式は成立しません。

**保存する個人情報を最小にする** — LINEのユーザーIDと表示名だけを持ちます。
氏名・電話番号・住所は保存しません。予約情報はホットペッパー側に置いたままにします。

**プッシュ配信はまだ使わない** — `src/line.js` に `push()` はありますが、
どこからも呼んでいません。フェーズ3で通数ガードを実装してから使います。
